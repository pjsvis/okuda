# The heuristics index — test-bearing rules, general and local

> The method applies to itself. When a practice works, the silo names it, gives
> it a test, and persists it — the corpus is the residue of that, and this index
> is the residue of the *residue*: the small rules we would want on a wall.
>
> **It is deliberately not a methodology.** No steps, no template, no ceremony.
> A framework built here would be the very thing it warns about — the
> **default shape** claiming the critique.

## The loop

**relevance → subtraction → invariants → verification → refuse the default**

- **Relevance.** Derive the boundary from the actual problem — the workflow — never from taste.
- **Subtraction.** Remove everything else. Removal is the *instrument of discovery*, not an economy.
- **Invariants.** What survives removal is the problem's shape: the things that must always hold.
- **Verification.** An invariant becomes a test. **Verifiability is downstream of subtraction** — you cannot state an invariant over a surface too large to hold one.
- **Refusal.** Reject the default shape, which imports boundary conditions that are not yours.

## The admission rule

**A heuristic is good when it names its own failure.** Test-bearing, or it is a
slogan — decorated Stuff. See `system.md` → **test-bearing**.

## General — portable to any silo

| heuristic | the rule | the test |
|---|---|---|
| **subtraction as discovery** | remove to reveal the invariant; the refusals are the non-modal information | can you state the invariant the removal revealed? if not, you removed by taste |
| **the default shape** | the solution handed to you before you asked your question — statistical + institutional poles | can you name whose boundary conditions it encodes? |
| **frame defaulting** | the prior is the mean of the training frame, applied regardless of the boundary conditions | does the derivation name the deviation it uses? |
| **audit surface** | visible addresses and citations make a document auditable *before* it is checked | do the lints cash the surface out, or is it polish? |
| **test-bearing** | admit a heuristic only if it names its own failure | state the observation that would show it false |
| **the moat question** | can you name your secrets? | if you cannot name it, it is an excuse |
| **benchmaxxing / muppet-exclusion** | the exam over the subject; gate on a *property*, not a *score* | is it a property or a score? can it be gamed? |
| **ventilator / wading** | apparatus you move *through*, defined by its inability to pause; the medium becomes the work | can you pause it without paying for the pause? |
| **Mercury tempo / fermata** | throughput that outruns intake reads as urgency and lands as exhaustion | is there a held beat at the boundary — can the reader breathe? |
| **cite or mark** | every claim carries a citation or a proposal mark | is this assertion unpriced? |

## Local — true of this silo

| heuristic | the rule | the test |
|---|---|---|
| **the workflow-derived boundary** | render what this workflow generates, and nothing else | does the actual workflow need it? (if yes, the exclusion is a defect, not a discipline) |
| **the three concerns** | compositing / windowing / rendering, one owner each | does it touch the byte stream's origin or the pane layout? then it is not ours |
| **text is the only wire** | ingress and egress are strings; no protocol, no daemon, no API | is the boundary a string, or a contract? |
| **the filesystem is the message bus** | files in, files out | does it need a service to exist? |
| **no parallel stores** | the index is truth for *contents*; the silo for *knowledge* | can it be deleted and regenerated from the silo? |
| **the resize contract** | fixed edges, one flex region, a degradation that is lossless or marked | does a resize force the reader to re-run the survey? |
| **renderer, not semantic layer** | draw the rail; do not interpret the document | does the decision change *meaning* or *rendering*? |
| **keep-class / refusals are the moat** | never delete a refusal; the record prevents re-deciding | is this tried-and-refused, or decided-and-undone? |
| **the one-way valve** | persisted documents cite callsigns and SHAs, never local ephemeral ids | does every citation resolve from the silo alone? |
| **invariant geometry** | the frame does not move; only the flex region does | does the reader's pre-conscious survey survive the change? |

## What this is not

- **Not a methodology.** The moment it acquires numbered steps and a template, it
  has become the **default shape** — and the critique is the product.
- **Not a checklist.** The tests are falsifiers, not boxes; a heuristic with no
  live test has been retired, not ticked.
- **Not closed.** A heuristic enters when it carries a test and has earned its
  place by use.
