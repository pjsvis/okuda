# The Outbound Vector Heuristic (OVH)

**Core Objective:** Disambiguate high-noise inputs (data, architectural proposals, rhetoric, or media) by evaluating **direction of travel** and **load-bearing utility** rather than debating labels or edge cases.

## 1. Default to the Shovel (Inversion of Burden)

* **Rule:** Every incoming artifact—whether a metric, a feature request, a UI element, or a verbal claim—starts in the **Outbound Queue** by default.
* **Mechanism:** Engage the **Justify Engine** immediately. An input does not earn space in your working context simply by existing or sounding plausible; it must actively prove it reduces uncertainty or drives a mechanical outcome.

## 2. Route by Vector, Not Taxonomy

* **Rule:** Never burn cycles categorizing *why* an input is bad (malicious spin, accidental bloat, aesthetic vanity, or legacy technical debt).
* **Mechanism:** Apply a binary routing check:
* **Inbound (Engine Room):** Directly constrains a real problem, exposes a failure mode, or carries verifiable signal.
* **Outbound (Wheelbarrow):** Consumes attention without changing the state of the system.


* **Benefit:** Eliminates taxonomic paralysis and prevents bad-faith actors from dragging you into semantic arguments over definitions.

## 3. Horizontal Sweep Over Vertical Hierarchies

* **Rule:** Do not build multi-tiered scoring systems ("critical noise," "moderate noise," "nice-to-have").
* **Mechanism:** Conduct a single horizontal pass across the entire input surface. Anything that fails the signal-to-noise threshold gets swept onto the same shovel simultaneously.

## 4. Return the Handle (Zero Lexical Exposure)

* **Rule:** When challenged on why an artifact was discarded, define the rejection purely by its **operational boundary**, never by attacking its subjective label.
* **Mechanism:** State what the system requires to function and hand the burden of proof back to the source. If they cannot demonstrate load-bearing utility, the item stays on the outbound trajectory.

**Quick Diagnostic Test:**
Before letting any input cross into your active workspace, ask one question: *If I strip away the presentation, the framing, and the decorative veneer, does the remaining core change my next action?* If the answer is no, it's already on the shovel.
