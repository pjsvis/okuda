# Conceptual Lexicon

**Status:** Append-only. Grows as terms are cited.
**Founded:** 2026-07-14. Split from `system.md` v1.1.0.
**Anchor:** Cited terms in briefs and decisions resolve here — the
semantic anchor the preflight audit checks against.

Protocol mechanics (locus tags, wrap-up) live in `system.md`. This file
holds silo-specific terms of art only.

**Append rule (usage-first):** a term is added when it has been used a few
times, *or* when it is sufficiently good that forgetting it would be a loss.

---

* **Locus tags** — *see `system.md` for the syntax and emission rule.* This
  entry holds the rationale. Locus tags section a multi-phase dialog for
  human navigation now and per-section compaction later. **Consumers:**
  human navigation of long dialogs (present) + per-section compaction into
  the handoff/review (future — see
  `briefs/2026-07-14-brief-locus-tag-consumer.md`). **Anti-ceremony:** omit
  on single-phase turns — a tag without underlying structure is entropy,
  not anti-entropy. **Prior art:** the parked brief
  `2026-07-12-token-compaction-hook.md` (appendix
  `technical-waypoint-injection-hooks`); revived here, scoped to navigation
  + compaction-ready (no `.td-memory/` substrate).

* **Wrap-up** — *see `system.md` for the instruction.* This entry is the
  compression: a one-word term for a multi-step closing instruction.
  Summarize, persist, note what's left, close the phase.

* **Predictably adequate** — the protocol's measured effect — not
  enhancement (ceiling stays) but normalisation (floor rises). Variance
  compresses 42%, 22/24 models deployable. *[Uncited figure — mark as
  impression until the eval is cited.]*

* **No muppets** — the sole model selection criterion. A muppet ignores
  constraints — agrees with everything, runs toward traps, produces
  decorated Stuff. The eval excludes muppets; personal experience selects
  from the candidates.

* **Benchmaxxing** — optimizing for benchmark performance rather than task
  performance — exam technique over the subject. The vendor's
  score-maximization. Can be gamed.

* **Muppet-exclusion** — the operator's admission gate — the inverse of
  benchmaxxing. Gates on a *property* (refusal under temptation), not a
  *score*. Cannot be gamed.

* **Stuff into Things** — the core transformation. Unstructured input
  ("Stuff") → structured output ("Things"). Decorated Stuff = format
  without substance.

* **Edge-lord** — the reference model, not the default. The benchmark that
  confirms the cheap model is good enough. Reserved for edge cases.

* **Pizza shop** — the metaphor for predictably adequate — consistent,
  acceptable output at sustainable cost. vs. **chip pan fire** — reactive,
  expensive, out of control.

* **The moat question** — "can you name your secrets?" The existential gate
  before the quality gate. If you can't, you don't have a moat — you have
  an excuse.

* **The Derrida question** — "should this even be in our consideration
  set?" External constraints (vendor, procurement, compliance) asked before
  the eval, not after.

* **Foxtrot-Oscar** — decline. From the phonetic alphabet. "Tell bad ideas
  to foxtrot-oscar."

* **Orthogonal by default** — most tasks in a brief are orthogonal to each
  other. This is the expected state, and it is what makes
  one-task-per-session possible. When tasks are *not* orthogonal, that is a
  signal, not a nuisance: a dependency usually indicates a missing boundary
  upstream. **A dependency is a finding.** See The Intention Loop, §4.

* **The gates** — the two admission checks applied to material in `docs/`:
  the **Derrida Gate** (should this even be in our consideration set?) and
  the **Foxtrot-Oscar Gate** (does it survive scrutiny?). See The Intention
  Loop, §8.

* **Marinade** — let a document sit, unworked, so it can be reviewed cold.
  Separates generation from judgment. The same context-clearing as a fresh
  session, applied to ideas.

* **Known position, bounded context** — the operating principle. Start from
  a known position, in a bounded context, with known aspirations and
  documented experience. The purpose of the record, TD, the gates, and the
  fresh session.
