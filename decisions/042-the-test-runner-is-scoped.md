# Decision: The test runner is scoped to the silo — `tmp/` is scratch, and a walker must not see it

**Date:** 2026-09-21
**Status:** Accepted

## Context

There was no `bunfig.toml`, so `bun test` used its default glob and walked the
whole tree. Measured 2026-09-21: **28 files** — 17 from `tests/`, and **11 from
`tmp/pretext/`**, a scratch checkout of an unrelated project with **zero tracked
files**.

`just test` was therefore red by 1, and the red was in the scratch tree:

```
(fail) the report server rejects stale requests and shuts down idempotently
```

**It does not reproduce in isolation, which is worse than a plain red.** Alone it
passes 17/17 across four runs, and in a 22-file subset it passes twice; only the
full 28-file walk fails it, and that it does in **3 of 3**. So the count is stable
while the *reason* is not discoverable from the failing test — it passes whenever
you go to look at it.

**And the obvious isolation is leaky.** `bun test <path>` is a *substring filter*,
not a scope: `bun test tests/` still loaded **22** files, including five from
`tmp/pretext/tests/`. Naming a directory does not bound the walk.

The silo's own suite, measured with the scratch tier excluded, is **421 pass, 7
skip, 0 fail across 17 files.**

## Decision

A `bunfig.toml` at the root excludes the scratch tier from the test walk:

```toml
[test]
pathIgnorePatterns = ["tmp/**"]
```

**Scope the walker, not the call site.**

## Alternatives Considered

| Alternative | Why Rejected |
|-------------|--------------|
| Put the flag in the `test` recipe (`bun test --path-ignore-patterns='tmp/**'`) | Fixes one call site. A bare `bun test`, an editor integration, or any future tooling stays leaky — and the leak is the kind you only notice when a test goes red for no reason |
| Change the recipe to `bun test tests/` | **Not a scope.** Measured: it is a substring filter and still loaded 5 files from `tmp/pretext/tests/` |
| Move the scratch tree outside the repo | `tmp/` is the documented scratch tier — `.gitignore:28`, *"regenerated by `just moira-pick`"*, never registered. The tree's layout is not the defect; the walker's default is |
| Delete `tmp/pretext` | It is a reference checkout the operator is studying, and it is gitignored by design. Deleting the evidence of a false red does not fix the mechanism that produced it |
| Leave it and document that `just test` is red by 1 | A red suite with no signal trains the reader to ignore it — and a red that will not reproduce in isolation cannot be investigated. This is the defect, not the workaround for it |

## Consequences

**What became easier:**

- `just test` is green: **421 pass, 7 skip, 0 fail across 17 files**, and it now
  means *the silo's tests pass* rather than *the silo's tests and a stranger's
  scratch checkout mostly pass*.
- A bare `bun test` is scoped too, so the fix reaches every caller rather than
  the one recipe that was edited.
- The non-reproducing failure leaves the gate's surface. A test that fails only
  when a stranger's suite runs alongside it is worse than useless in a suite you
  are trying to baseline.

**What became harder:**

- Nothing about the silo's own tests. The pattern excludes `tmp/` only, so a test
  added anywhere else is still discovered.
- A second scratch directory would need a second pattern — the exclusion is
  declared, not derived, and a declaration can go stale.

**Constraints this imposes:**

- **`tmp/` must stay the scratch tier's name.** The exclusion is a literal
  pattern; renaming the scratch directory silently re-opens the leak.
- The `test` recipe keeps `@bun test` and gains no flag, so the scope lives in one
  place rather than two that can disagree.

## Notes

- **The third instrument-scope finding of the day, and the first where the
  artifact was right.** `facade-lint.sh` reported a violation it had not computed
  (`ADR-GATE-NAMES-041`); the briefs index asserted `open` for states it could not
  represent; here a checker walked a directory no tracked file lives in. All three
  are a check answering a question about the wrong thing.
- **`bun test <path>` is a filter, not a scope.** This is the trap worth carrying:
  a positional argument that *looks* like a directory bounds nothing, and the
  failure mode is a test from somewhere else appearing in your run.
- **A failure that will not reproduce in isolation must not be baselined.** The instinct on meeting a
  red suite is to record the count and move on. Here the count was right and the
  reason was wrong — and the test passed 4/4 in isolation, so a baseline would
  have recorded a number that no isolated run reproduces.
