# Decision: Herdr is the reference host for the pair; Rex is demoted with a receipt

**Date:** 2026-11-13
**Status:** Accepted
**Enforced by:** `scripts/probe-surface.ts` — the Herdr branch reads
`~/.config/herdr-app/themes/*.json` and `settings.json`, so a pair on that host
is dereferenced rather than judged by eye (`tests/surface.test.ts`, four cases:
16 slots, three keys, selection, malformed settings). The Rex side is **advice**
until its host reports.

## Context

The pair needs a host that can *hold* a declaration and let it be read back.
Rex Beta was the working host and its theme slot failed three independent tests
in one sitting (2026-11-13):

1. `com.superlogical.terminal.set_theme` — accepted (`{}`) and inert, plain and
   as the owning client, with the screen colour census unmoved.
2. A generated custom theme — written into `Workspace.customThemes`, read back
   by `just surface-probe` (the file held the probe's pair), selection **dropped**
   at launch: `darkThemeID` returned to `merino-dark`.
3. The app's **own** custom theme id in the dark slot — also dropped, and the
   experiment left *both* appearance slots on builtin defaults
   (`merino-dark`/`merino-light`), costing a light selection that had stood for
   weeks. The custom set is still in the array; the selections are not held.

No readback exists on that side: `format` with `extra_palette` returns plain
text, `rex config` has no theme keys, `rex actions` offers one theme action.

Against that, Herdr: the pair is a **file** (`~/.config/herdr-app/themes/gloam.json`,
three keys moved, 16 ANSI slots carried), already generated by
`just herdr-theme` from `PAIRS[8]`, readable without asking any process
anything. `AGENTS.md:24` already names Herdr as the host for windowing, and it
runs on both the macOS desk and Omarchy — which is the second provider.

## Decision

**Herdr is the reference host for the figure-ground pair. Rex stays in the
consideration set only as a *reported* defect, not as a working surface, until
it holds a selection and reports its state.**

## Alternatives Considered

| Alternative | Why rejected |
|---|---|
| Keep working Rex | Three one-way levers and no readback: every failure is ambiguous between our artifact and its slot, so the work cannot converge |
| Drop the pair requirement and keep whatever the host ships | The requirement is control over the pair; `#0d1117/#e6edf3` at 16:1 is what the host ships, and the operator's complaint about it is the reason the work exists |
| A `HostPin` abstraction over both hosts | Rule of three, and worse: one arm of the interface would be shaped by a host that cannot report. Two siblings sharing `PAIRS` is proportionate |
| Judge Herdr by eye, as Rex was judged | The eye is the instrument that failed: a look cannot distinguish "not selected" from "selected and wrong" |

## Consequences

**What became easier:**

- The pair on Herdr is now **dereferenced**: `just surface-probe` prints each
  theme's pair, its ratio, its verdicts, whether it is selected, and whether it
  carries 16 ANSI slots. That last count is the Rex failure made visible: a
  three-key pin is now *reported* as one.
- Two providers become possible: Omarchy (sRGB, no P3 anywhere) and macOS. A
  failure on one and not the other localises the fault to the pipeline instead
  of leaving it between artifact and host.
- The theme zoo is auditable without opening it: on this machine
  `atom-one-dark` reads 7.2:1 with 12 roles not navigable, `win98` reads 1.8:1
  with 16 not readable, and `gloam` reads 10.6:1, readable and navigable.

**What became harder:**

- `just herdr-theme` writes outside the silo. That is a crossing, and it owes a
  declaration (what was written, where, who owns the commit) — the script already
  prints it.
- Herdr's *selection* is not always a file: `settings.json` carries a `theme`
  key only when it was set that way, and the picker's choice is written nowhere
  this probe can read. The probe says so rather than guessing, which means the
  selection half of the reading is absent on a picker-driven setup.
- The Rex light slot is now on a builtin pair (`merino-light`, 15.8:1, 16 roles
  under the floor) instead of the custom one that was selected before. Restoring
  it is the operator's edit in the app, not a write: the app demonstrably
  overwrites what we put there.

## Constraints

- **The pair is generated, never typed.** `just herdr-theme` reads `PAIRS`; the
  pin moves three keys and carries the ANSI slots through untouched.
- **The probe reads, the eye confirms.** A pair change is accepted only after
  the probe names it; a screen that looks different with no probe reading is not
  evidence of anything.
- **Rex owes a receipt, not more attempts.** The three tests above are the
  report. Further work on that slot is refused until the host answers a query
  about its own palette.
